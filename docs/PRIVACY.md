# 隐私与能力边界

## 工具自身的数据流

运行时仅通过本机进程管理 API 读取进程 PID、父 PID、所属用户、启动时间、可执行路径，以及识别 Node/Bun 入口所需的命令行。匹配不依赖 Claude 账号或配置。界面会显示识别结果及本地路径；不要把包含私人路径的结果截图随意公开。

本项目没有实现 HTTP 请求、DNS 查询、上传、遥测、自动更新或外部网页打开逻辑。检查/关闭不会主动联系 Claude 或 Anthropic，也不需要填写账号。不会改动代理、防火墙、网络设置或 Claude 配置，不会删除聊天记录或项目文件。强制结束运行中的任务仍可能使未完成的操作中断。

安装/解压为本地复制。GitHub 下载、Git 推送，以及开发者构建时获取 .NET / NuGet / GitHub Actions 依赖会访问相应服务；这些操作与应用运行时不同。

## 为什么无法承诺“绝不泄漏真实 IP”

关闭工具不是防火墙，也不是网络流量代理。

1. 点击工具之前，Claude 可能已经建立连接或发送请求。
2. 为了允许正常退出，工具会先请求关闭桌面应用并短暂等待。正在退出的 Claude 仍可能在这个时间段自行联网。
3. 即使强制结束进程，也无法撤回服务端已经收到的数据、记录的 IP 或已经发送的数据包。
4. 工具显示的是检查时可见的进程状态，无法永久阻止 Claude 被用户、更新器或其他软件重新打开。
5. 网页版、远程、Cowork/其他虚拟机、系统服务、WSL/容器及不可追溯孤立任务的网络活动，不能靠本工具完整管理。

准备切换代理时，对覆盖范围内的进程应先关闭 Claude，再确认检查完整且无残留，最后切换网络。如果有残留、受保护进程或读取失败，应先处理该结果。使用 Cowork 等范围外功能时，应另行停止与核实，不能把本工具的零进程结果作为它们也已经关闭的证据。需要严格限制网络出口时，应在系统或网络层实现隔离；本项目不自动配置这些规则。

例如，Anthropic 的 [Windows 官方部署说明](https://support.claude.com/en/articles/12622703-deploy-claude-desktop-for-windows) 明确说明，Cowork 的虚拟机由后台服务运行。本工具限定当前用户/会话，不停止系统服务或共享的虚拟化服务，也不检查虚拟机内部进程。

## 不会上传到仓库的内容

仓库只包含项目源码、文档、构建脚本和工作流。Claude 账号配置、聊天记录、API Key、用户进程快照、个人笔记、`.DS_Store`、本地构建临时文件不会随源码提交。发布 ZIP 由 GitHub CI 从已提交源码构建。Git 提交使用 GitHub noreply 邮箱，避免发布本机配置中的个人邮箱。
