# 进程边界复查记录

本记录描述 1.0.2 的审查重点。测试通过只证明已覆盖场景，不能证明所有启动方式和竞态都不存在问题。

## 安装目录与源码目录相互独立

macOS 安装器把两个完整 `.app` 复制到 `~/Applications/Claude一键工具/`，桌面入口指向安装后的应用。应用所需图标、签名与可执行文件均在自己的 bundle 内，动态库只依赖系统框架，不引用最初生成源码的目录。

因此，移除早期原型目录不会卸载正式应用。需要卸载时，应移除安装目录与桌面入口。维护中的源码应另外保留在 Git 工作目录或远端仓库。

## 本轮重点

- **父 PID 复用**：进程的父 PID 可能来自较早的快照，不能仅因为相同 PID 当前属于 Claude 就认领子任务。需要同时核对身份，以及子进程创建时间不早于父进程；无法确认的祖先保护链不能授权结束。
- **Node/Bun 入口**：区分有值选项、无值选项与执行模式。未知 `--option=value` 不能一律跳过后把尾随数据当作脚本；`--eval`、`--print`、Node `--run` 等不等同于直接运行 CLI 文件。
- **可疑但不能确认的入口**：无法解析的参数或被改写的启动标题，不能仅凭文本授权结束。存在明确 Claude 启动线索却无法确认时，应提示检查不完整，避免无条件报告“已关闭”。
- **读取失败和恢复**：已追踪任务临时不可读取时，不能直接忘记它的身份。恢复可读后需要继续复核；祖先无法核实时的保护规则，也必须覆盖这类已捕获目标。

回归测试使用合成快照和自行创建的无害进程，避免通过关闭用户真实 Claude 来做验证。发布检查同时在 Windows x64、Windows ARM64、Intel Mac、Apple Silicon Mac 运行；实际结果以对应标签的 Actions 记录为准。

## 仍然存在的能力边界

进程快照无法永久阻止软件重新启动；已经失去可追溯关系的任务、定制启动器以及未来未知版本可能无法识别。未知线索提示不完整，也不代表那个进程一定属于 Claude。

macOS 的身份读取与 `kill` 仍是两个系统调用，复核只能降低而无法从接口上彻底消除极短时间窗口中的 PID 变化风险。Windows 的最终结束动作使用持有并复核过的进程句柄。两者都不应被描述为对所有时序和所有进程的绝对保证。

工具没有运行时网络上传逻辑，但无法撤回 Claude 已发送的数据，也不能保证退出前不发生网络通信。详细说明见 [隐私与能力边界](PRIVACY.md)。
